# Грузовые вагоны в разборе — заметки для работы

Сайт: один `index.html` (Three.js r128 из `three.min.js`, без сборки). Вкладки = объекты в `WAGONS`
(`GONDOLA`, `BRAKE_RIG`, `BOGIE_DET`…), у каждого `S` (узлы), `P` (детали), `STEPS` (экскурсия), `build(root)`.

Ключевые механизмы в `index.html`:
- `add(parent, geo, color, partId, x,y,z, opts)` — меш детали; регистрирует его в `REG.meshesOf[partId]` и `REG.pickables`.
- `node(parent, e => [dx,dy,dz])` — группа, которая сдвигается при «Разборке» (e = 0…1).
- `applyVisual()` — подсветка, рентген, изоляция узла: меняет `opacity`/`emissive` материалов по `partId`.
- Координаты сцены: x — вдоль вагона, y — вверх, z — поперёк; метры. Колея 1520, R колеса 0.4785.

## Модели из Blender

Детализированные детали делаются скриптами в `blender/` и экспортируются в `models/*.glb`.
- `blender/wagonkit.py` — общие функции: строим в координатах сайта, экспорт glTF (+Y up) пишет те же координаты.
  Свойство объекта `part` уходит в glTF extras → `userData.part` → деталь из `W.P`.
- Один скрипт = одна деталь: `build()` и `OUT`. Добавить его в `PARTS` в `blender/build.py`.
- Пересобрать все модели: `python3 blender/build.py` (модуль `bpy` 5.2) или `blender -b -P blender/build.py`.
- На сайте: `glbPart(parent, 'models/x.glb', {pos, rot, part, fallback:[меши-примитивы]})`.
  Пока файл грузится или если не загрузился (сайт открыт с диска), остаются примитивы из `fallback`.
- В живом Blender (MCP) скрипты подтягиваются с GitHub raw этой же ветки — правим файл, пушим, перезапускаем.

Подвижные детали (шток, рычаги, тяги) пока остаются примитивами: их двигает `ctx.update(b)` в `BRAKE_RIG`.
Для замены таких деталей модель режется по шарнирам, начало координат — в оси вращения.

Превью-артефакт на claude.ai не отдаёт `.glb`: для него модель конвертируется во встроенный glTF с именем `*.gltf.json`.
